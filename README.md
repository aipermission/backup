# AIPermission Backup

Self-hosted encrypted backup storage for
[AIPermission](https://github.com/aipermission/aipermission).

The service stores immutable `.aipdb` snapshots that AIPermission has already
encrypted with SQLCipher. It can list and return those snapshots, but it cannot
decrypt them and never receives the database password, gateway vault key, MCP
tokens, or connector credentials as separate values.

## Security Boundary

This repository is a passive blob store, not a remotely hosted AIPermission
gateway. It has no accounts, team model, command execution, connector access,
browser session, or SaaS control plane.

The recommended deployment is one backup service shared by the owner's trusted
computers over a private local network. Keep the raw service port private and
publish it through an HTTPS reverse proxy; non-loopback AIPermission clients
reject plaintext HTTP. When clients must connect across different networks,
place the service behind a VPN or private overlay network and keep HTTPS enabled
inside that network. Direct exposure of the backup port to the public internet
is not the recommended deployment.

An encrypted database copy still enables offline password guessing if storage
is compromised. AIPermission therefore applies a stronger database-password
gate before enabling remote backup. The service checksum detects corruption; it
does not prove that a malicious storage operator has not replaced both a blob
and its metadata.

## Quick Start

Create a high-entropy bearer token without committing it:

```bash
mkdir -p secrets
openssl rand -hex 32 > secrets/backup-token
chmod 640 secrets/backup-token
printf 'AIPERMISSION_BACKUP_SECRET_GID=%s\n' "$(id -g)" > .env
chmod 600 .env
docker compose -f docker-compose.release.yml pull
docker compose -f docker-compose.release.yml up -d
```

Compose mounts the token as a file and adds only its host group ID to the
non-root service process. The token does not become a container environment
variable. Both `.env` and `secrets/` are git-ignored; keep the token readable by
its owner and group only.

The example Compose file binds the service to `127.0.0.1:8080`. For access from
another trusted computer, publish it through an HTTPS reverse proxy and keep the
raw service port private. For access across the internet, use a VPN or private
overlay network rather than exposing the service port directly. AIPermission
rejects plaintext non-loopback provider URLs.

The release Compose file defaults to the pinned `0.1.0` image. Set
`AIPERMISSION_BACKUP_VERSION` explicitly when upgrading. Contributors can use
`docker compose up -d --build` to build the development image from source.

Check the local service:

```bash
curl http://127.0.0.1:8080/healthz
curl \
  -H "Authorization: Bearer $(cat secrets/backup-token)" \
  http://127.0.0.1:8080/v1/info
```

Do not put the token in shell history on shared machines. A Docker secret or a
root-readable secret file is preferred over the environment-variable fallback.

## Storage

The persistent `/data` volume contains:

```text
/data/metadata.db
/data/blobs/<stream-id>/<backup-id>.aipdb
/data/temporary/
```

Uploads are written to a temporary file, hashed with SHA-256, flushed, and
atomically renamed before metadata is committed. Startup removes abandoned
temporary uploads and resumes any blob cleanup queued by a completed prune or
explicit selected-version deletion. Every stream retains at least one recovery
version.
Backup IDs are immutable and generated by the service.

Metadata includes stream and backup IDs, database display name, source
installation ID, timestamp, byte size, checksum, and storage path. It never
contains the database password or decrypted database content.

## Configuration

| Variable | Default | Purpose |
| --- | --- | --- |
| `AIPERMISSION_BACKUP_LISTEN_ADDR` | `127.0.0.1:8080` | HTTP listen address |
| `AIPERMISSION_BACKUP_DATA_DIR` | `/data` | Persistent storage root |
| `AIPERMISSION_BACKUP_TOKEN_FILE` | none | Preferred bearer-token file |
| `AIPERMISSION_BACKUP_TOKEN` | none | Token fallback; minimum 32 characters |
| `AIPERMISSION_BACKUP_MAX_UPLOAD_BYTES` | `2147483648` | Maximum request body size |

Exactly one token source is required. The token file takes precedence.

## Protocol

The versioned API is documented in [docs/api.md](docs/api.md). Mutation and
listing requests require `X-AIPermission-Protocol-Version: 1`; `/v1/info` is the
authenticated compatibility discovery endpoint.
